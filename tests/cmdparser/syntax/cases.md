# 语法级测试用例（syntax）

> 关注：输入行如何被切分、规范化并被 `InputParser::parse` 转为 `Command`。
> 判定基准：见 `../README.md`「通用通过 / 失败判定标准」。

## CP-S 用例清单

### CP-S-001 标准指令完整解析
- **场景**：合法的点分指令。
- **前置**：`InputParser` 就绪；schema 含 `mine.start --layer`。
- **输入**：`mine.start --layer 2`
- **步骤**：构造并调用 `parse`；断言返回。
- **预期**：`verb == "mine.start"`；`options["layer"] == "2"`；`args` 为空；`raw == 原输入`。
- **验证重点**：verb 点分名、命名参数剥离 `--` 前缀后正确入 map。

### CP-S-002 空行输入
- **场景**：用户直接回车。
- **前置**：`parse` 函数可调用。
- **输入**：`""`
- **步骤**：调用 `parse("")`。
- **预期**：`verb` 为空串；不进入语法解析逻辑；不抛异常。
- **验证重点**：空输入短路分支，`raw` 仍保留原输入。

### CP-S-003 首尾空白
- **场景**：前后多余空格。
- **前置**：同 CP-S-001。
- **输入**：`"  mine.start --layer 1  "`
- **步骤**：调用 `parse`。
- **预期**：视为合法指令解析成功，`verb == "mine.start"`；`raw` 保留原样含空格。
- **验证重点**：CLI11 对首尾空白容错；`raw` 与解析结果分离。

### CP-S-004 连续多空白
- **场景**：令牌间多个空格。
- **输入**：`mine.start     --layer    2`
- **预期**：正常解析，`options["layer"] == "2"`。
- **验证重点**：空白序列安全折叠，无多义参数误判。

### CP-S-005 Tab 分隔
- **场景**：以 Tab 分隔的词元。
- **输入**：`mine.start\t--layer\t2`
- **预期**：按空白分词正确解析（若解析失败则返回 `verb="error"` 且不崩溃）。
- **验证重点**：Tab 被当作有效分隔符或至少被安全拒绝；标注实际 CLI11 行为。

### CP-S-006 缩写别名（仅当系统支持别名时执行）
- **场景**：别名 `m`→`mine`、`n`→`north`。
- **前置**：**仅当**系统正式支持别名扩展时才执行本用例，否则跳过并在报告标注“别名未实现”。
- **输入**：`m --layer 1`、`m`、`n`
- **步骤**：先经别名扩展层再入 `parse`。
- **预期**：`m --layer 1` 归一为 `mine.start --layer 1`；单一 `m` / `n` 分别归一为 `mine` / `north`。
- **验证重点**：别名映射前后解析结果一致，无递归别名死循环。

### CP-S-007 未知指令
- **场景**：语法正确但未定义的动词。
- **输入**：`go north`、`look rock`
- **预期**：现行 schema 下无 `go`/`look` 子命令 → 解析返回 `verb="error"` 或派发返回 `UnknownCommand`；不崩溃、不误路由到其他 handler。
- **验证重点**：未知动词不触发现有后端逻辑。

### CP-S-008 `--help` 帮助请求
- **场景**：请求帮助。
- **输入**：`mine.start --help` 或 `--help`
- **步骤**：调用 `parse`。
- **预期**：捕获 `CallForHelp` → 返回 `verb="help"`；不打印到终端、不退出进程。
- **验证重点**：`--help` 归一到 `help` 分支，调用方统一打印帮助。

### CP-S-009 超长输入
- **场景**：远超合理长度的输入。
- **输入**：10,000 字符超长串（含合法前缀 + 超长填充）。
- **预期**：进程不崩溃、无异常上抛；按现有逻辑返回 `verb="error"` 或安全截断。
- **验证重点**：长度边界下的稳定性与防御性处理。

### CP-S-010 非法选项
- **场景**：调用未知选项名。
- **输入**：`mine.start --bogus 3`
- **预期**：CLI11 拒绝未知选项 → 返回 `verb="error"`；不调用任何后端 handler。
- **验证重点**：未知选项被安全拒绝。

### CP-S-011 缺少必填参数
- **场景**：必填项缺失（语义亦覆盖，此处验证句法层拒绝）。
- **输入**：`mine.start`、`time.scale`
- **预期**：`mine.start` 因缺 `--layer`、`time.scale` 因缺 `--factor` 返回 `verb="error"`；不进入业务。
- **验证重点**：`required()` 选项缺失时被正确拒绝。

### CP-S-012 SQL 注入特征字符
- **场景**：注入特征字符串作为参数值。
- **输入**：`mine.start --layer "1'; DROP TABLE ore; --"`
- **预期**：字符被当作普通字符串参数值处理；**不执行**任何 SQL 语义；不崩溃、不误分发；`verb` 为预期值（若 CLI 拒绝则 `verb="error"`）。
- **验证重点**：数据与指令语法完全隔离，无注入面。

### CP-S-013 脚本注入特征字符
- **场景**：Shell/脚本注入特征。
- **输入**：`mine.start --layer "$(rm -rf /)"`、`mine.start --layer "1 | cat /etc/passwd"`、`quit && rm -f *`
- **预期**：所有输入仅作参数数据/命令串处理；**绝不产生 shell/命令执行**；反射/反馈时不二次求值。
- **验证重点**：命令解析器与系统调用层面均无注入。

### CP-S-014 Emoji 输入
- **场景**：非 ASCII 表情符号。
- **输入**：`⛏ mine.start --layer 1 ⛏`、`MINE ⛏ COPPER`
- **预期**：UTF-8 字节被安全处理；要么被拒绝返回 `verb="error"`，要么作为参数保留；进程不崩溃、无乱码导致的解析崩溃。
- **验证重点**：Unicode/多字节在 CLI11 内的健壮性。

### CP-S-015 非法分隔符 / 混合特殊字符
- **场景**：分隔符滥用与特殊符号集。
- **输入**：`mine.start ,;:!@#$%^&*() = --layer 1`、`--layer` 值含 `_-.()`
- **预期**：或在参数中被转义为字面量，或被安全拒绝为 `verb="error"`；不产生意外分流；不崩溃。
- **验证重点**：特殊符号不干扰 verb 派生与选项归属。

### CP-S-016 大小写差异句法级
- **场景**：动词大小写。
- **输入**：`MINE.START --layer 1`、`Time.Now`、`QUIT`
- **预期**：Connector 层小写归一后路由（见 `CP-L-004`）；CLI11 子命令大小写匹配行为**需确认**——若 CLI11 区分大小写，则上层大小写输入返回 `verb="error"`。
- **验证重点**：区分 CLI11 句法匹配层与 Connector 路由层两段的大小写策略。
