# 上下文级测试用例（context）

> 关注：玩家/全局状态与权限门槛是否在**正确阶段拦截**命令，避免越权触发后端。
> 状态来源：`Model/Playerstates`（眩晕、死亡）+ `MiningState`（采矿中硬直）。
> 判定基准：见 `../README.md`「通用通过 / 失败判定标准」，尤其“错误路径 handler 不得被调用”。

## CP-C 用例清单

### CP-C-001 空闲态启动采矿
- **前置**：玩家空闲（`MiningStatus::Idle`），等级/资源校验通过，在矿洞内。
- **输入**：`mine.start --layer <合法层>`
- **预期**：进入 `Mining`；`layer_id`/`start_time` 写入；返回成功提示与期望层。
- **验证重点**：Idle → Mining 合法跃迁，状态字段正确初始化（含计时点）。

### CP-C-002 采矿中重复启动（硬直拦截）
- **前置**：当前已在采矿（硬直）。
- **输入**：`mine.start --layer <另一层>`
- **预期**：**被拦截**，提示“已在采矿中/动作冷却”；不覆盖当前会话层、不重置计时点；后端子控制器不二次 `start`。
- **验证重点**：采矿中不接受重复 `start`，会话数据不被破坏。

### CP-C-003 眩晕状态输入采矿/移动
- **前置**：玩家处于**眩晕**（stun）。
- **输入**：`mine.start --layer 1`、`go north`
- **预期**：在派发到后端前被状态守卫拦截，提示“眩晕中无法行动”；`MiningStatus` 不被改动。
- **验证重点**：眩晕在正确阶段（进入 handler 之前）拦截，且对采矿与移动均生效。

### CP-C-004 死亡状态下输入任意动作
- **前置**：玩家处于**死亡**（dead）。
- **输入**：`mine.start --layer 1`、`go north`、`time.scale --factor 2`
- **预期**：动作被拦截，返回死亡提示（如“你已死亡”）；`HandlerContext.handler` **不被调用**。
- **验证重点**：死亡是全网关，任何指令不得触发后端副作用；日志记录死亡拦截。

### CP-C-005 采矿中发起移动（硬直队列/拦截）
- **前置**：采矿中，玩家尝试移动。
- **输入**：`go north`
- **预期**：按设计被拦截（提示“采矿中无法移动”）或进入延迟队列；无论如何**不得中断/覆盖采矿会话**。
- **验证重点**：硬直对移动指令的拦截语义与采矿会话的完整性。

### CP-C-006 采矿中 quit / save
- **前置**：采矿中。
- **输入**：`quit`、`save`
- **预期**：明确并一致：拦截或放行，两者最终结果可预期（不丢失未结算产出、不回滚异常）；若放行 `quit` 则先结算或明示丢失。
- **验证重点**：状态敏感命令在采矿硬直下的契约一致性（需在实现中定死并配对验证）。

### CP-C-007 等级权限不足
- **前置**：玩家 `mining_level` 低于目标矿层需求（如核心层需 15，玩家仅 1）。
- **输入**：`mine.start --layer 4`（核心层）
- **预期**：被权限守卫拦截，提示“采矿等级不足”；不进入采矿；不产生产出。
- **验证重点**：等级门槛在进入控制器结算前拦截。

### CP-C-008 工具/照明前置不满足
- **前置**：`MiningContext` 中 `has_torch=false`、`has_lantern=false` 且当前层要求照明，或工具档位不合法。
- **输入**：`mine.start --layer <深层>`
- **预期**：在 `start` 前置校验被拦截，提示缺少照明/有效工具；无 `MiningStatus` 变更。
- **验证重点**：设备+照明前置校验的覆盖面与拦截时机。

### CP-C-009 停止后恢复可再次采矿
- **前置**：已在采矿，随后 `mine.stop`（硬直结束）。
- **输入**：`mine.stop` → `mine.start --layer <层>`
- **预期**：`stop` 后回到 `Idle`（结算产出、复位状态）；再次 `start` 成功进入新会话。
- **验证重点**：Mining → Idle 复位完整，且 Idle 可再入（无残留脏状态）。

### CP-C-010 `mine.status` 不改变状态
- **前置**：空闲态与采矿中各查一次。
- **输入**：`mine.status`
- **预期**：仅查询只读返回当前状态/目标层，**不**改变 `MiningStatus`、不结算产出。
- **验证重点**：查询命令无副作用。
