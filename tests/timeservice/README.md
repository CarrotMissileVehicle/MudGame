# MUD 游戏时间管理模块测试总览（TimeService / Tick Manager）

本目录面向游戏时间管理模块 `src/Model/Timeservice` 编写测试方案。测试按**测试方向**细分目录，
每个方向下放置 `cases.md` 用例文档。与 `tests/cmdparser` 的语法/语义/上下文/逻辑分层不同，
时间模块属于**纯模型服务**，无命令解析入口与会话上下文，故按**能力维度**（Tick、倍率、精度、
日历事件、定时器、取消重置、时钟异常、并发负载）组织。

## 被测对象与职责边界

被测核心为：

- `mud::time::GameDateTime`（`game_time.h`）：显式日历字段，最小粒度=分钟，纪元=0年1月1日 00:00；
  提供 `total_minutes()` 与 `advance(minutes)`（分→时→日→月→年进位，负值夹紧到纪元）。
- `mud::TimeService`（`time_service.h/.cpp`）：帧驱动时间推进 + 定时回调调度器。

职责边界（依赖方向 Model，仅被 Controller / View 调用）：

| 接口 | 签名 | 行为口径 |
| --- | --- | --- |
| 构造 | `TimeService(GameDateTime initial={0,1,1,0,0})` | 初始化当前游戏时间 |
| 当前时刻 | `now()` | 返回显式日历字段，无秒 |
| 会话总分钟 | `session_total()` | 距纪元总分钟数 |
| 推进一帧 | `update()` | 等效 1 现实秒，受 `time_scale` 影响；亚分钟满 60 进位 1 游戏分钟 |
| 直接设时 | `set_time(t)` | 覆盖当前时刻并清空亚分钟余数 |
| 流速 | `set_time_scale(double)` / `time_scale()` | 默认 60（游戏秒/现实秒） |
| 一次性定时 | `schedule_time(due, cb)` → token | 到期触发，触发后移除 |
| 周期定时 | `schedule_interval(minutes, cb)` → token | 首期=now+minutes，每期后自动续排 |
| 退订 | `cancel(token)` | 按令牌移除队列条目 |

> **仅测试时间管理模块本身**，不得扩展到采矿、天气、农场等无关系统。跨模块联动（如采矿读条
> 依赖定时器）仅以“定时器取消防幽灵结算”的方式覆盖（见 `cancel_reset/`）。

## 通用通过 / 失败判定标准

对时间模块统一按以下判定（具体到用例另附预期）：

1. **时间推进**：`now()` 与 `session_total()` 在给定 `update()` 次数与倍率下的期望值一致
   （可用独立公式重算，不允许用被测代码自身结果做期望）。
2. **倍率换算**：累加 `time_scale`（游戏秒）后按 `floor(总游戏秒/60)` 进位整数分钟，余数进入
   `sub_minute_` 不丢弃；换算结果与浮点精确累加后的期望误差在阈值内。
3. **回调触发**：仅在 `(before, after]` 窗口内到期的条目被触发且仅触发一次；窗口外不得触发。
4. **回调顺序**：同帧多到期按 `due` 升序、同位次再按 `token` 升序；顺序错误判失败。
5. **取消**：取消后同帧到期**不得**触发（防幽灵结算）；取消不存在令牌为无害空操作。
6. **异常输入**：`time_scale<0`、`gp_minutes<=0`、空回调等不崩溃、不误触发、不污染状态。
7. **日志/观测**：关键操作（推进跨界、触发、取消、设时、变速）产生可校验的日志条目。

## 精度与性能指标总则

| 指标 | 验收阈值 | 度量方式 |
| --- | --- | --- |
| 延时任务到期触发误差 | ≤ 50ms（若以真实时钟驱动） | 注册 `schedule_time` 后按帧推进，记录实际触发墙钟偏移 |
| 帧驱动到期误差 | 目标帧内，不跨帧 | 单帧 finally 位置记录触发帧号 |
| 长时间运行漂移 | 累计游戏分钟与按倍率期望分钟偏差窗口内 0，长期无系统性漂移 | 连续 N 帧 + 每帧 `session_total()` 对比 |
| 批量触发耗时 | 万级条目单帧处理 < 阈值（如 100ms） | 计时器/探针埋点 |
| 内存 | 取消/到期后队列条目数回落，无泄漏 | 快照队列大小 |

> 时间模块以**帧驱动**为唯一时间源（外部游戏循环调 `update()`），非真实墙钟驱动；因此
> “到期触发误差 ≤ 50ms”的量化目标仅在以**真实时钟/墙钟**驱动（或接 `timespec` 系统时钟）的
> 扩展形态下适用，当前帧驱动形态以“目标帧内不跨帧”为准（见 `timer_queue/`）。

## 风险与已知缺陷清单（对应关键风险）

> 以下风险均针对**当前实现**逐条核实：

| # | 关键风险 | 当前实现状态 | 验证位置 |
| --- | --- | --- | --- |
| R1 | **幽灵结算**：取消定时器后仍被执行/结算 | 已实现 `cancel(token)`，需验证取消后同帧到期不触发 | `cancel_reset/` |
| R2 | **时间倒流导致冷却异常**：`set_time` 回拨后 `session_total()` 非单调 | 当前 `set_time` 直接覆盖，无单调保护 | `clock_anomaly/` |
| R3 | **系统时钟前跳**：跨过到期时刻导致事件全部错过（丢失） | 当前 `update()` 只处理一帧窗口，大跳变会丢事件 | `clock_anomaly/`、`timer_queue/` |
| R4 | **周期定时漂移**：大倍率跨多周期时只补一次并重排到 now+period | 当前实现可跨周期跳过，需明确语义并验证 | `timer_queue/` |
| R5 | 倍率精度：非整倍率（如 `1/3`）浮点累计长跑漂移 | 当前算法可保持，需量化 | `precision/` |
| R6 | 日出 06:00 / 日落 18:00 / 季节切换全局事件 | **当前未实现**事件系统，属扩展需求 | `calendar_event/` |
| R7 | NTP 时钟跳变自修正 | **当前未实现**系统时钟驱动与自修正 | `clock_anomaly/` |

> R6 / R7 为**需求目标形态**，当前代码不满足。相关用例标记为 **P3 / 扩展**，并注明
> “实现后回归执行”；`R1~R5` 直接针对当前代码可执行。

## 观测与日志验证方式

- **帧序号探针**：在 `update()` 调用点埋点，记录帧号与 `now()`、`session_total()`、队列大小。
- **回调旁路记录**：回调内追加记录（令牌、`due`、触发帧号、墙钟时间戳）到全局向量供断言。
- **事件序列校验**：用记录序列比对期望触发顺序，作为“事件触发正确性”判据。
- **队列快照**：批量注册/取消后断言 `schedule_` 条目数，验证无泄漏、无重复条目。
- **时间戳双写**：对时钟跳变场景，同时记录帧内 `before/after`，校验窗口语义。
