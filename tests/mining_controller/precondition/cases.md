# 采矿前置条件测试（precondition）

> 关注：进入采矿前**必须满足**的所有前置条件，以及前置不满足时是否在正确阶段拦截、有无副作用。
> 判定基准：见 `../README.md`「通用通过 / 失败判定标准」之状态守恒、副作用守恒；错误路径 handler **不得**进入结算。
> 代码现状：等级/照明/层越界已在 `can_enter_layer` 校验；**矿镐存在、镐耐久、背包、矿脉储量、玩家离线**为未落地字段（目标形态）。

## MIN-PR 用例清单

### MIN-PR-001 无矿镐启动采矿
- **前置**：玩家空闲、等级/照明满足，但背包无采矿工具。
- **输入**：`mine.start --layer <合法层>`，工具槽为空。
- **预期**：前置校验拦截，提示「未装备矿镐」；不进入 `Mining`；无状态/产出副作用。
- **验证重点**：工具存在性是首个硬门槛，拦截发生在进入控制器结算之前。

### MIN-PR-002 矿镐耐久为 0（损坏）
- **前置**：持有矿镐但 `durability == 0`。
- **输入**：`mine.start`。
- **预期**：拦截并提示「矿镐已损坏，请维修或更换」；不进入采矿；不产生读数动作。
- **验证重点**：耐久为 0 视为不可用，与「无矿镐」等价处理。

### MIN-PR-003 矿镐耐久恰好够一次轮询
- **前置**：`durability == 1`。
- **输入**：`start` → 一次 `poll`（interval 到期）。
- **预期**：本次轮询正常产出；结算后耐久归 0，工具进入损坏态；不得出现耐久为负。
- **验证重点**：耐久扣减下界为 0，不溢出为负（不变量）。

### MIN-PR-004 背包格子满启动
- **前置**：背包所有格子已满（无空格放新矿石）。
- **输入**：`mine.start`。
- **预期**：按设计拦截「背包已满，无法采矿」或允许采但产出落袋/邮件；两者只能取其一并固定为设计契约。
- **验证重点**：背包满时行为契约一致，且不会导致产出凭空丢失。

### MIN-PR-005 负重超限启动
- **前置**：背包未满但负重已达到上限。
- **输入**：`mine.start`。
- **预期**：按设计在启动前置或结算时拦截/降级（提示负重超限）；不产生无法拾取的产出。
- **验证重点**：负重判定时机（启动 vs 结算）与提示一致性。

### MIN-PR-006 矿脉储量已空启动
- **前置**：目标矿脉 `reserve == 0`（已采空）。
- **输入**：`mine.start --layer 1`。
- **预期**：拦截并提示「该矿脉已采空」；不进入 `Mining`；不扣减、不产出。
- **验证重点**：储量 0 的矿脉不可再进入，防负库存。

### MIN-PR-007 矿脉储量低（恰好剩 1）启动
- **前置**：目标矿脉 `reserve == 1`。
- **输入**：`mine.start`。
- **预期**：允许启动；结算时按储量上限产出（最多 1 次），储量归 0 后停止产出。
- **验证重点**：低储量下产出数不超过剩余储量，不变量守恒。

### MIN-PR-008 玩家离线
- **前置**：玩家会话已注销/离线。
- **输入**：离线下收到采矿指令或轮询请求。
- **预期**：指令被拒绝或产出落袋由登出逻辑接住（邮件/待领）；不产生针对空玩家的副作用。
- **验证重点**：离线玩家不持有会话状态，结算归属明确。

### MIN-PR-009 采矿等级不足
- **前置**：`mining_level` 低于目标层需求（如 core 需 15，玩家仅 1）。
- **输入**：`mine.start --layer 4`。
- **预期**：拦截并提示「采矿等级不足」；不进入采矿；不产出（已实现：`can_enter_layer`）。
- **验证重点**：等级门槛在进入控制器结算前生效。

### MIN-PR-010 照明不足
- **前置**：`has_torch/has_lantern` 不满足目标层要求（middle 需火把、crystal/deep 需求见数据、core 需灯笼）。
- **输入**：`mine.start --layer <照明要求层>`。
- **预期**：拦截并提示缺少照明；`MiningStatus` 不变（已实现：`can_enter_layer`）。
- **验证重点**：照明校验覆盖面与拦截时机（已覆盖 middle 火把 / crystal 灯笼）。
