## 模块范围与职责

采矿玩法以 `MiningHandler` / `MiningController` / `MiningState` 为核心组件：

- **MiningHandler**：面向命令层的 `start / poll / stop` 会话入口，持有会话状态并转发给控制器。
- **MiningController**：会话启动、进度更新（`update`）、停止结算（`stop_mining`），结合 `Ore::OreData` 与 `mining_layers.json` 生成随机产出。
- **MiningState**：会话状态机（`Idle ↔ Mining`），维护目标层、开始时间、最近计时点。
- **数据**：`ore.json`（矿石属性）、`mining_layers.json`（层等级/照明）、`spawn_rates.json`（产出分布）。

层索引（与 `state_gate_test.cpp` 一致）：`0 shallow(等级1,无照明) / 1 middle(等级3,火把) / 2 deep(等级5,火把) / 3 crystal(等级8,灯笼) / 4 core(等级15,灯笼)`。

## 业务链路五阶段

1. **采矿前置检查**：矿镐存在性、镐耐久、背包状态、矿脉储量、玩家状态（空闲/眩晕/死亡）、照明、等级。
2. **采矿中状态控制**：读条、`BUSY` 锁定、禁止移动/攻击/交互、采矿中断、完成时间结算。
3. **采矿成功结算**：产出抽取、背包/背包容纳、矿脉储量扣减、矿镐耐久扣减、经验结算。
4. **异常处理**：断电、服务崩溃、网络异常、数据库写入失败的回滚。
5. **资源刷新**：矿脉采空提示、刷新触发、刷新数量、重复刷新、跨服同步。

## 领域边界与本模块实现现状

当前代码已实现**状态机（Idle↔Mining）、层等级/照明前置、按 interval（游戏分钟）的轮询产出**。

以下业务能力**当前尚未落地**，相关用例标记为「目标形态」并按设计验收：

- 矿脉储量（reserve）字段与扣减
- 矿镐耐久（durability）字段与损耗
- 背包容量 / 负重限制
- 数据库事务与断电回滚
- 资源刷新调度
- 多玩家并发抢矿的锁机制
- 玩家离线 / 背包满载的落地产出 / 邮件补发

## 通用通过 / 失败判定标准

1. **副作用守恒**：一次合法轮询/结算只产生一次「储量 -1、耐久 -1、矿石 +1」，无重复产出或漏产出。
2. **状态守恒**：状态机仅在合法路径跃迁（`Idle ↔ Mining`）；错误路径不得把状态改掉、不得触发结算。
3. **不变量校验**：任何时刻不得出现负库存、负耐久、矿石数量溢出的背包。
4. **原子性**：储量、耐久、背包三处写操作要么全部成功、要么全部回滚（出错时无部分成功）。
5. **统计合规**：大样本掉落分布与 `spawn_rates.json` 配置一致（误差区间见 `probability/`）。
6. **并发安全**：多人抢同一低储量矿脉时，总产出不超过其初始储量。
7. **可恢复性**：断电/崩溃后基于持久化快照可恢复到一致状态，不丢产出、不重复发放。
8. **异常兜底**：任何输入（高频请求、越界层、损坏工具）不导致崩溃、无未捕获异常、无误结算。
