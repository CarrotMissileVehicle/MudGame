# 资源刷新测试（resource_refresh）

> 关注：矿脉被采空后的提示、刷新触发条件、刷新数量、重复刷新、跨服同步与持久化。
> 判定基准：刷新不变量——刷新前后设定一致、不重复刷、跨服一致；见 `../README.md`。
> 代码现状：矿脉储量与刷新调度为未落地能力（目标形态）。

## MIN-RF 用例清单

### MIN-RF-001 采空提示
- **前置**：矿脉 `reserve` 由 1 被采到 0。
- **输入**：最后一次成功结算成功 / 之后请求采矿。
- **预期**：明确提示「矿脉已采空」；继续访问被拒；无负产出。
- **验证重点**：采空态的收敛提示与访问控制。

### MIN-RF-002 刷新触发条件（时间 / 消耗阈值）
- **前置**：矿脉采空，设置刷新周期（如 N 游戏分钟）或消耗阈值。
- **输入**：推进到刷新时刻。
- **预期**：矿脉重新可采，`reserve` 恢复到配置满值。
- **验证重点**：刷新触发按 time_service 周期判定的正确性。

### MIN-RF-003 刷新数量为配置满值
- **前置**：刷新触发。
- **输入**：读取新 `reserve`。
- **预期**：等于 `spawn_rates.json`/层配置的满储量；若有随机波动则在配置范围内。
- **验证重点**：刷新数量与配置一致，无越界（不可超上限、不可为 0 无限刷）。

### MIN-RF-004 重复刷新（未到周期）不生效
- **前置**：矿脉刚刷新尚未采空。
- **输入**：再次触发刷新任务。
- **预期**：跳过刷新（守刷新时间戳/状态位）；`reserve` 不重置、不重复加量。
- **验证重点**：刷新幂等，防腐重复刷出无限矿产。

### MIN-RF-005 刷新不覆盖在采玩家会话
- **前置**：刷新时刻恰有玩家正在采该脉。
- **输入**：刷新执行。
- **预期**：玩家当前会话产出按旧储量结算或安全迁移；不因刷新导致玩家矿石/储量双重发放。
- **验证重点**：刷新与活跃会话的互斥/一致性。

### MIN-RF-006 跨服 / 地图同步一致
- **前置**：多服实例 / 分片持有同一矿脉视图。
- **输入**：刷新或采空在 A 服发生。
- **预期**：B 服经同步后持有相同储量；无 A 有 B 无或状态漂移。
- **验证重点**：刷新状态广播 / 同步的最终一致性。

### MIN-RF-007 重启后刷新状态持久化
- **前置**：采空后未刷新，进程重启。
- **输入**：重启读取矿脉。
- **预期**：从持久化恢复「已采空 + 刷新时间戳」；不因重启把采空脉重置为满（防刷）或丢失刷新计划。
- **验证重点**：刷新状态随持久化持久，重启不破坏不变量。

### MIN-RF-008 刷新与并发结算交错（总量守恒）
- **前置**：刷新任务与玩家结算并发触碰同脉。
- **输入**：并发执行。
- **预期**：行锁/事务隔离保证总量守恒；既不因刷新丢产出，也不因竞态负库存。
- **验证重点**：跨事务的资源生命周期一致（与 TX-007 呼应）。
