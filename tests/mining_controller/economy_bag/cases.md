# 经济与背包结算测试（economy_bag）

> 关注：产出（矿石 + 经验）如何落袋、工具耐久损耗、包满/负重/掉落的结算策略。
> 判定基准：副作用守恒 + 不变量（无负耐久、无背包越界）；见 `../README.md`。
> 代码现状：产出生成已有，**背包容器、耐久损耗、掉落、邮件补发**为未落地字段（目标形态）。

## MIN-EC 用例清单

### MIN-EC-001 背包有格时正常落袋
- **前置**：背包有空格，产出一份矿石。
- **输入**：`poll` 到期产出一份 `MiningResult`。
- **预期**：矿石进入背包（数量累加或叠新格）；背包总量 +1；经验累加。
- **验证重点**：产出正确写入背包与经验结算。

### MIN-EC-002 背包满时产出落袋（按设计落到邮箱/丢弃）
- **前置**：背包已满。
- **输入**：`poll` 产出一份矿石。
- **预期**：按设计契约二选一——产出进「待领/邮件」或明确丢弃并提示；**不得**静默吞没。
- **验证重点**：包满结算策略固定且可预期，产出不凭空消失。

### MIN-EC-003 负重超限时产出降级
- **前置**：负重已近上限。
- **输入**：产出被拒/降级。
- **预期**：超限部分进入待领/邮件或拒绝本次结算并提示「负重超限」；总负重不超上限。
- **验证重点**：负重结算边界，防负重溢出。

### MIN-EC-004 矿镐耐久正常损耗（每次轮询 -1）
- **前置**：`durability=S`，一次 session 采 N 次。
- **输入**：N 次 `poll` 到期。
- **预期**：`durability = S - N`；N=S 时归 0 进入损坏态，后续拒绝。
- **验证重点**：耐久与产出次数一一对应，不一次多扣、不遗漏。

### MIN-EC-005 耐久归 0 后继续轮询
- **前置**：`durability=0`。
- **输入**：再次 `poll`。
- **预期**：该次不再产矿石（无耐久不可采），会话按设计结束或提示「矿镐损坏」；耐久不为负。
- **验证重点**：耐久下界 0 的不变量。

### MIN-EC-006 工具损坏提示与替换
- **前置**：耐久 0 提示后。
- **输入**：换新工具 → 重新 `start`。
- **预期**：换工具后可再次正常采矿，`interval` 按新档位生效。
- **验证重点**：工具损坏→替换→恢复链路完整。

### MIN-EC-007 经验结算正确
- **前置**：产出 `experience` 定义明确（如按层与矿石）。
- **输入**：一次产出。
- **预期**：经验按 `MiningResult.experience` 累加；跨会话累计无回退。
- **验证重点**：经验不丢、不重复、可累计。

### MIN-EC-008 稀有矿石占格/叠加上限
- **前置**：矿石单格叠加上限定义明确（如 999）。
- **输入**：累加至上限后再产出。
- **预期**：达上限后不再叠加进该格，分配新格或拒绝并存档；数量不溢出。
- **验证重点**：统计数据结构不越界，无 int 溢出。

## 自动化建议

- 背包/耐久逻辑建议抽为纯函数并以内存容器替身直测，杜绝 DB/网络依赖。
- 关键断言：耐久=产出次数差、背包净增量=成功产出一致、包满/负重分支有明确终态。
